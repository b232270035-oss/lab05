**Оюутны нэр:** Д. Дэлгэрмаа  
**Оюутны код:** b232270035

## Орчны хувилбар

```text
$ node -v
v20.20.2
$ newman -v
6.2.3
```

`server.js` нь Node.js-ийн суурь `http` модулийг ашиглана. Серверийг `node server.js` командаар эхлүүлж, `http://localhost:3000` хаягаар ажиллуулна. Collection-ийн `baseUrl` хувьсагчийн анхны утга энэ хаяг. Энэ лабораторийн ажиллуулах орчинд 3000 порт өөр процесс эзэлж байсан тул Newman-ийн нотолгоог `PORT=3100 node server.js` командаар авч, ажиллуулахдаа `--env-var baseUrl=http://localhost:3100` гэж override хийсэн.

## Тестийн сонголт ба төлөөлөх утгууд

| Сонголт | Хүчинтэй / төлөөлөх утгууд | Буруу буюу сөрөг утгууд |
|---|---|---|
| `studentID`-ийн төлөв | Бүртгэлтэй, `status=active`; бүртгэлтэй, `status=inactive` | Оюутны бичлэг байхгүй |
| Оюутны үзсэн хичээл (`coursesTaken`) | Шаардлагатай бүх холбоос хичээлийг үзсэн; заримыг нь үзсэн; холбоос хичээлгүй үед хоосон массив | Холбоос хичээл шаардсан ч оюутан хоосон массивтай буюу аль нэгийг нь үзээгүй |
| `courseID` | Бүртгэлтэй хичээл | Бүртгэлгүй хичээл |
| Холбоос хичээл (`prerequisites`) | Бүгдийг үзсэн; заримыг үзсэн; огт үзээгүй; хоосон жагсаалт | — |
| POST хүсэлтийн талбарууд | `studentID` ба `courseID` хоёулаа байна | Аль нэг талбар дутуу: HTTP 400 `ERROR_BAD_REQUEST` |
| Давхар алдааны тэргүүлэх дараалал | Оюутан идэвхгүй бөгөөд хичээл байхгүй | Хариу нь `ERROR_INACTIVE_STUDENT`; API оюутны төлөвийг хичээл хайхаас өмнө шалгана |

## Тестийн спецификаци

| № | Тохиолдол | Гол нөхцөл | Хүлээгдэх статус | Хүлээгдэх `result` |
|---:|---|---|---:|---|
| 1 | Happy path | Идэвхтэй оюутан холбоос хичээлүүдийг бүгдийг үзсэн, бүртгүүлэх хичээл байна | 201 | `OK` |
| 2 | Идэвхгүй оюутан | Оюутан байна, `status=inactive` | 200 | `ERROR_INACTIVE_STUDENT` |
| 3 | Байхгүй оюутан | Хичээл байна, оюутны бичлэг байхгүй | 200 | `ERROR_NO_STUDENT` |
| 4 | Байхгүй хичээл | Оюутан идэвхтэй, хичээлийн бичлэг байхгүй | 200 | `ERROR_NO_COURSE` |
| 5 | Холбоос хичээлээс нэгийг ч үзээгүй | Хичээлд хоёр холбоос хичээл шаардсан, оюутны `coursesTaken` хоосон | 200 | `ERROR_PREREQUISITES` |
| 6 | Холбоос хичээлээс заримыг үзсэн | Шаардлагатай хоёр холбоос хичээлийн нэгийг үзсэн | 200 | `ERROR_PREREQUISITES` |
| 7 | Хязгаар: холбоос хичээлгүй хичээл | Идэвхтэй оюутан, хоосон `coursesTaken`, хоосон `prerequisites` | 201 | `OK` |
| 8 | Хязгаар: `studentID` дутуу | `courseID` өгсөн, `studentID` байхгүй | 400 | `ERROR_BAD_REQUEST` |
| 9 | Хязгаар: `courseID` дутуу | `studentID` өгсөн, `courseID` байхгүй | 400 | `ERROR_BAD_REQUEST` |
| 10 | Давхар алдаа | Оюутан идэвхгүй ба хичээл байхгүй | 200 | `ERROR_INACTIVE_STUDENT` |

Collection-д эдгээр 10 тохиолдол тус бүр өөрийн setup PUT хүсэлтүүдийг ажиллуулж, дараа нь POST хийдэг. Байхгүй оюутан/хичээлийн кейст тухайн бичлэгийг зориуд үүсгэхгүй. Амжилттай кейсүүд `registrationID`-ийн яг утгыг шалгахгүй, тоон утгатай байгааг л шалгана. Урьдач нөхцөлийн кейсүүд `missing` массивыг мөн oracle-оор батална. Тиймээс үндсэн collection-д **10 test script, 24 assertion** ажиллана.

## Newman-ийн үр дүн

`results/newman-pass.txt` файлд үндсэн collection-ийн бүрэн гаралт байна: **24 assertion ажилласан, 0 алдаа, exit code 0**.

`results/newman-fail.txt` файлд зөв collection-оос тусдаа `lab05-collection-fail.json` байна: happy path-ын статусын oracle-г зориуд 200 гэж буруу хүлээлгэсэн. Гаралт **24 assertion ажилласан, 1 алдаа, exit code 1** гэж харуулна.

`results/newman-down.txt` файлд сервер унтарсан үед collection ажиллуулсан бүрэн гаралт байна: **ECONNREFUSED**, 27 хүсэлт амжилтгүй, Newman-ийн exit code **1** (24 assertion бүгд failed гэж тоологдсон). Энэ нь сервертэй холбогдох боломжгүй интерфейсийн алдаа; хариу ирээгүй тул статус болон JSON oracle шалгагдах нөхцөл бүрдээгүй. PASS/FAIL-ийн oracle-ийн алдаа нь сервер хариу өгсний дараа хүлээгдсэн утга бодит утгатай зөрөхийг хэлнэ.

## 5 алхмын дизайны дүгнэлт

1. Бие даан тестлэгдэх функцээр `POST /registrations`-ийг сонгосон.
2. Оюутны төлөв, үзсэн хичээл, хичээлийн оршин байгаа эсэх, холбоос хичээл, request-ийн заавал талбаруудыг сонголт болгосон.
3. Сонголт бүрд эерэг, сөрөг болон хязгаарын төлөөлөх утгуудыг тодорхойлсон.
4. Нөхцөлүүдийг хүснэгтээр нэгтгэж, үндсэн үр дүн бүрт спецификаци гаргасан.
5. Спецификаци бүрийг setup, POST болон статус/утгын oracle бүхий тусдаа collection кейс болгосон.
6. Хамгийн их бодол шаардсан хэсэг нь давхар алдаатай үед аль алдаа түрүүлж гарахыг тогтоох байв.
7. Идэвхгүй оюутан ба байхгүй хичээлийг хослуулахад API `ERROR_INACTIVE_STUDENT`-ийг буцааж, шалгалтын дарааллыг ил болгосон.
8. Эдгээр тест серверийн өгөгдсөн хэрэгжүүлэлтээс гэнэтийн согог илрүүлээгүй.
9. Зориуд буруу болгосон oracle FAIL үр дүнг гаргасан бөгөөд DOWN үр дүн хүсэлт очоогүй интерфейсийн алдааг харуулсан.
10. Бие даасан setup болон яг утга тулгадаггүй `registrationID` oracle нь давтан ажиллуулахад үр дүнг тогтвортой байлгасан.
